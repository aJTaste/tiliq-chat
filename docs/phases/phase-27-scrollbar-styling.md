## Phase 27 の実装内容・詳細

`docs/backlog.md`の実機フィードバック由来の小粒課題「スクロールバーの見た目を自前で整えたい（特にチャット画面で目立つ）」に対応。Phase 26に続き、ユーザーのClaude Pro契約終了当日の残り時間で着手した2件目。

### 概要

ブラウザデフォルトのスクロールバーはブランドトーン（落ち着いた帯模様のニュートラル基調）から浮いて見える、というフィードバックへの対応。`app/globals.css`に全称セレクタでスクロールバーのスタイルを一括適用し、細め・`--band`ベースの控えめな見た目に統一した。tongueブルーは「CTA・リンク・強調に限定使用」というデザイン原則（CLAUDE.md）を踏まえ、スクロールバー自体には使っていない。

### 変更ファイル

- `app/globals.css` — `scrollbar-width`/`scrollbar-color`（Firefox系の標準プロパティ）と`::-webkit-scrollbar`系疑似要素（Chromium/Safari系）の両方を追加。全称セレクタ（`*`）で一括適用するため、チャットのメッセージ一覧・サイドバー・モーダル等、個別コンポーネントの変更は不要だった

### DB変更

なし。

### 設計判断・学び

- スコープを「チャット画面だけ」に絞らず全称セレクタで一括適用したのは、`* { overflow: auto/scroll }`を持つ要素（サイドバーの会話一覧・モーダル内リスト等）が今後増えても個別対応が要らないようにするため。ユーザーからの要望も「特にチャット画面で目立つ」という例示であり、他画面への適用を禁止する趣旨ではないと判断した
- スクロールバーの色にtongueブルーを使わなかったのは、CLAUDE.mdのデザイントークン表に明記された「tongueはシグネチャーカラー（CTA・リンク・強調に限定使用）」という原則をそのまま適用した結果。常時表示されるスクロールバーにアクセントカラーを使うと「希少に使う」という設計意図と衝突するため

### 検証方法・実施内容

- `npx tsc --noEmit`（エラー0件。CSSのみの変更のため実質影響なし）
- `npm run build`（`next build`、成功）
- CSSのみの変更のためESLintは対象外（`.css`はconfig対象外である旨の警告のみ）
- ブラウザでの実際の見た目確認（ライト/ダーク双方、Chromium系/Firefox系のレンダリング差異含む）はこのセッションでは行っていない

### 動作確認してほしい項目（2026-08-18 実機確認済み）

- チャットのメッセージ一覧・サイドバーの会話一覧など、縦スクロールが発生する箇所でスクロールバーが細め・bandトーンで表示されること
- ライトモード・ダークモード双方で違和感がないこと（`--band`/`--ink-muted`はモードごとに値が変わるため、自動的に追従するはず）
- 主要ブラウザ（Chrome/Edge = `::-webkit-scrollbar`系、Firefox = `scrollbar-width`/`scrollbar-color`）双方での見た目
